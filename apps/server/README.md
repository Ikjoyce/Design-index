# Local server

Phase 1 Hono API and background worker host. Owns the loopback-only HTTP API, authenticated capture intake, job queue, analysis orchestration, and access to local storage. Keep provider keys on the server and bind to `127.0.0.1` only.

Implemented: image/isolated URL intake, protected assets, search/edit APIs, session bootstrap, and an embeddable server with graceful shutdown. The Go worker automatically runs leased analysis/prompt stages for new inspiration once key/model/sharing prerequisites are met; isolated evaluation trials remain explicit. Call/token history, validation, provenance, and consent/review APIs are local; allowance/billing controls belong to Go. Capture uses a separate bounded worker and supports an injected `pageCapturer` for tests; evaluation uses the injected AI provider. Keys are passed only by the server entrypoint; importing the server factory does not read `.env` or provider credentials. See the root README and `docs/capture-evaluation.md` for commands, endpoints, and security limits.

The standard entrypoint also watches the project-root `inbox/` for stable PNG/JPEG/WebP files. `DESIGN_INDEX_INBOX_DIR` accepts another absolute path or `off`. Embeddable `startServer({ inboxDir })` explicitly opts in; omitted/null leaves folder intake disabled. The bounded polling worker uses existing `saveImage()` validation/deduplication and AI queues, writes a durable import ledger, never changes source files, skips links/subdirectories, and drains on shutdown. Authenticated `/api/inbox` and `/api/inbox/retry` expose status/retry, not arbitrary path selection. There is no new filesystem-watcher dependency or extra model provider.
